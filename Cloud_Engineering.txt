Cloud Computing{
    Allows businesses to be flexible and effortlessly scale or modify their resources according to their needs by renting servers

    Core Concepts{
        Cloud Models{
            Cloud Service Models{
                SaaS (Software as a service)(Applications fully built and hosted by the cloud provider)

                FaaS (Funciton as a service)(Small pieces of code that runs on certain triggers from other services)

                PaaS (Platform as a service)(A development and deployment environment fully built by the provider for clients to just build their apps in)

                IaaS (Infrastructure as a service)(Hardware providers rent to clients for them to fully manage their virtual resources on)
            }

            Shared Responsibility Model (Cloud companies secure the main hardware setup, while you protect your own app and data inside it)

            Cloud Deployment Models{
                Public Cloud (Your infrastructure is in a shared server with other clients renting resources.)

                Private Cloud (Your infrastructure having its own private dedicated servers on premises or in a data center)

                Hybrid Cloud (Combining both public and private for flexibility between both benefits)

                Multi-Cloud (Using multiple cloud platforms for their individual strengths)
            }
        }

        Edge computing (Processing data right where it's collected instead of sending it far away to a main server)

        Virtualization (Lets one computer run multiple isolated virtual machines at the exact same time using software.)

        Virtual Machine (A fake, software-based computer that runs inside your real computer)

        Serverless computing (The cloud provider handles all the server operations, you build apps and only pay when your code is running on the servers)

        Colocation (Renting space in a third party data center to put your own physical servers, cooling and network infrastructure)

        SKU (Stock Keeping Units) (The available tiers for certain resources indicating perks and price for each tier)
    }
}

                    Backup Center (Central UI console for easily managing all your backup needs across all your services)

                    Recovery Point Objective (RPO) (The maximum amount of data loss measured in time that your company can take){
                        so if you have a RPO of one hour, you should perform backups every hour to ensure that if an hour's worth of data is lost
                        in a disaster, you can recover all that data, but if more than an hour's worth of data is lost you can only restore the data up
                        to 1 hour's worth of changes, the rest is permanantely lost and unrecoverable.
                    }

                            Standard Tier (the main storage inside the vault itself. This is where most of your backups live day-to-day.)

                            Archive Tier (cheap, long-term cold storage for old backups you rarely need, Slowest to restore)

                Azure Site Recovery (To ensure high availability by automaically setting up backup resources or infrastructure in different locations){
                    Starting failover (the swap from primary to secondary site is initiated)
                    Committing failover (all final states of the primary's data are being saved to the secondary site)
                    Failover confirmed (the secondary site is up and running)
                    Failover committed (the primary site is now shut down or ready to be the new backup/secondary site)

                    failover is the 4 phase process (primary to secondary)

                    then reprotection is initiated so the primary stays up to date with the secondary as it is being used as the new primary

                    then failback is the 4 phase process again (secondary back to primary)
